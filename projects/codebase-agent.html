Codebase Q&A Agent

A local, zero-cost AI agent that answers questions about a codebase using RAG, tool-calling, and conversational memory — no API keys, no cloud costs, runs entirely on-device.

GitHub ↗ Read the build log →
codebase-agent — local terminal

Overview

Point this agent at any code repository and ask it questions in plain English — "how does the login flow work," "find all the TODO comments," "what files exist in this project." It decides which tool to use, retrieves the right context, and answers — all running locally with no API costs. Built to be the AI-stack half of a capstone project: RAG, tool-calling, and agent memory, learned by building rather than by tutorial.

Features

  • Semantic search over an entire codebase using local embeddings and a vector database
  • Agentic tool-calling — the model picks between semantic search, exact keyword search, and file listing based on the question
  • Multi-repo support with scoping — query one project or search across several at once
  • Conversational memory for natural follow-up questions
  • Runs 100% locally via Ollama — zero API cost, zero cloud dependency

Technology stack

Python Ollama ChromaDB Sentence Transformers RAG Tool-Calling

Challenges

  • Hallucinated folder structure. The agent confidently listed folders that didn't exist in the real repo — the vector store had no chunk describing the actual project structure, so the small local model filled the gap from its training data. Fixed by generating a real folder-tree chunk during ingestion.
  • Follow-up questions with pronouns. "Which file handles that?" initially searched for the literal word "that." Passing conversation history into the tool-router improved the failure mode from confidently wrong to honestly uncertain — but fully resolving pronouns turned out to be a genuine capacity limit of a 1.5B-parameter model, not a prompting bug. Documented as a known limitation.
  • Batch size limits. Naively ingesting an entire repo (including node_modules) produced 17,000+ chunks and broke ChromaDB's insert batch size — fixed with proper exclusions and batched inserts.
